## 3. sm_120 QLoRA 与三坑 smoke

配置:E4B、bitsandbytes NF4 double quant、bf16 compute、LoRA `r=8/alpha=16/all-linear`、SDPA、`max_length=2,048`、seed 20260811。20 条冻结掩码样本中,截断后仍保留监督 token 的 14 条进入 smoke。

| 探针 | 结果 |
|---|---|
| `use_cache=false` 对照 | 5/5 step,loss 全有限,2,646.73 input tok/s,峰值 allocated/reserved 50.21/53.00 GiB |
| `use_cache=true` 主线 | **20/20 step 通过**,loss 全有限,2,894.78 input tok/s,峰值 allocated/reserved **50.44/53.04 GiB** |
| bf16 | GPU 原生支持;本次 forward/backward 全程 bf16 compute,未见 fp16 mask 溢出 |
| 模板 | 训练目录模板 SHA 与冻结值完全一致 |

本次短 smoke 未复现 `use_cache=false` 发散,但不足以推翻已知风险;正式训练固定 `use_cache=true`,不开 gradient checkpointing。原 E4B QLoRA“~17GB”估计被本配置实测否定。

FlashAttention 进一步核对后不再消费。RTX PRO 6000 是 GB202 / SM120,与 B200 的 GB100 / SM100 并非同一 kernel 目标;E4B 文本层又混合 `head_dim=256` 的滑窗注意力和 `global_head_dim=512` 的全局注意力。当前 FA4 的 SM120 路径不能可靠覆盖这两个维度,FA2 也不能覆盖 512 维全局层,因此两者都不是 E4B 整模训练后端。已取消约 1.036GB 的 FA2 下载与中继,主线固定已实测通过的 SDPA;未执行 `pip install flash-attn`,也未编译源码。

## 4. Teich 20 条尖峰与降级决策

Teich 0.3.3 的 API 可调用,但与门⑦冻结语义**不兼容**:

- 20 条中仅 prepare 13 条;7 条因 `unsupported_tool_call` 被丢弃。
- 剩余 13 条与冻结 renderer 比较,token 精确相等 0/13,mask 精确相等 0/13。
- Teich audit 另报 5 条监督区包含 `<|tool_response>` 边界。

因此按执行卡 §2.6 选择 `fallback_m0_renderer`,继续复用 `scripts/m0/data/render_linec_samples.py`;没有放宽审计或把不兼容伪装成通过。`scripts/m1/run_teich_mask_spike.py` 可复现诊断并产出 20 条冻结 renderer 样本。

## 5. Seed 纪律

`configs/m1/seed_policy.yaml` 将数据顺序、初始化、rollout 与 trainer data seed 统一记录为 `20260811`。只承诺 seed 可审计,不承诺逐 bit 确定性;后续 candidate 快照必须引用该文件并写入实际 seed。
