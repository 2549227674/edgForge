## 移交事实

- RK3588 / RKLLM 1.3.0 下，E4B W8A8 / 16K 只有 1-core 能初始化；1-core 是诊断工件，不是交付形态。
- 3-core 在单个 4 GiB IOVA domain 中短缺 44,933,120 B。扩大 aperture、RK3588 W4A16 和 domain 改写三条路线均已关闭。
- S2b 的 H2/H3 未归因；owner 接受该未知并冻结 M0，不继续 X4、H2 粒度阶梯或 S3。
- 手动模板下 `thought` / `tool_call` 标记结构可行，但未验证完整语义。
- 板端只保留 `/home/orangepi/edgeforge_m0_frozen_r2/` 中的 1-core 工件；云端 M0/X5 工作目录已删除。

## 不得自动启动的工作

- 正式校准集或 N/2N logits 收敛实验。
- `w8a8_g128/g256` 精度阶梯。
- thought/tool_call 完整语义构造。
- 上下文压缩、prompt cache、吞吐、时延、定频和核数曲线。
- 3-core、32K/131K、driver/DT/kernel 或 `.so` 修改。

上述工作若要开始，必须有新的 owner 授权、新执行卡、新 manifest 和新证据目录。

## 3-core 重开的必要条件

至少出现一项外部变化：

1. 厂商 toolkit/runtime 支持 RK3588 W4A16 或其他显著缩小权重块的格式。
2. 厂商 BSP/driver 更改 IOMMU aperture，或提供可审计的多 domain 同时可见设计。
3. 更换硬件或受支持的平台合同。

即使条件成立，也必须由 owner 明确撤销冻结。不得复用 X0–X5 的运行目录或将新结果追溯改写为 M0 结论。
