## 关键实测结论

### 本地 Agent 链路

Pi 在独立 worktree 中完成了故意植入的 `calculator.py` bug 修复：读取文件、运行 pytest、编辑实现、再次运行 pytest，最终 `1 passed`。session 中已读回 `CUSTOM_ENTRY_OK`，并保留了结构化工具事件。

Pi 没有确认到原生 max-turn 控制；外层 wall-clock timeout 可停止 Pi，但一次预算探测显示工具子进程需要由 W1 的 `AgentRunner` 用进程组清理机制兜底。因此采用：

```text
use_pi = conditional
W1 guard = wall-clock deadline + tool-call counter + process-group cleanup
```

### Terminal-Bench

TB 2.1、Harbor、Docker、任务镜像、Oracle 与 verifier 已形成有效闭环。早期失败来自 Docker Hub/GitHub 下载的网络中断；这类结果不解释为 Oracle 或模型能力失败。后续正式评测应使用串行或低并发，并保留容器代理配置。

### RKLLM 板端

板端已移除旧 v1.2.x SDK/runtime 资源，安装官方 RKLLM v1.3.0 用户态 runtime 和 header；未升级内核 NPU driver。官方 v1.3.0 `llm_demo` 已在板上原生构建，并成功以 runtime 1.3.0 初始化一个既有 Qwen 1.2.1 模型，说明：

```text
RKLLM runtime 1.3.0 + RKNPU driver 0.9.8 + 既有 .rkllm 模型 = init success
```

这证明用户态升级可用，但不是 Gemma4 转换或性能验收；Gemma4 仍须用 v1.3.0 toolkit 单独转换并验证。
